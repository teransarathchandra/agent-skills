# Role profile: data and analytics

Load this when the person works with data: analysis, BI, data engineering, data science, ML. Follow it for intake, evidence, CV shape, keywords and screening answers.

## Titles and adjacent roles

- Common titles: Data Analyst, BI Analyst or Developer, Analytics Engineer, Data Engineer, Data Scientist, Machine Learning Engineer, Reporting Analyst.
- Realistic moves after a layoff: analyst to analytics engineer or data engineer; BI to data analyst in another domain; data scientist to ML engineer; business analyst to data analyst.
- Search the person's title plus "analytics", "insights" and "reporting".

## Evidence sources

- Dashboards and reports: Power BI, Tableau, Looker. Screenshots with data removed, plus who used them and how often.
- Pipelines and models: dbt projects, Airflow DAGs, SQL, notebooks, repos. Use the person's own commits.
- Outcome records: decisions a report changed, revenue or cost effect, forecast accuracy, hours saved. Use only what the person can source.
- Documents: stakeholder praise, project write-ups, performance reviews.
- Public: Kaggle or personal projects on public data, a portfolio. Private under an NDA: employer or client data, customer records, internal metrics, real dashboards. Rebuild a sample on public data instead.

## Intake questions

1. Which kind of data work is the strength? (answer as it is: analysis, BI, engineering, science, ML)
2. Which direction do you want?
   a) **Same role and level (Recommended: strongest evidence)**
   b) Analyst toward data engineering or analytics engineering
   c) Toward data science or ML
   d) Other: type it
3. Where is the proof of your work? (pick any)
   a) **Reports and dashboards with outcomes (Recommended: shows impact)**
   b) Repos, notebooks or pipelines
   c) Documents and praise messages
   d) Other: type it
4. Do you hold a data certification? (answer as it is: name and issuer, or none)
5. Can you share a public project?
   a) **Yes, one on public data (Recommended: safe and clickable)**
   b) No, all work was private
   c) Other: type it

## CV shape

- Order: header, summary, skills (SQL, BI tools, languages, cloud), experience, projects, certifications, education.
- Summary leads with years, the data stack, the domain and the type of decisions supported.
- Bullets, action then result then how:
  - "Cut weekly reporting from 12 hours to 1 by replacing spreadsheets with a Power BI model and a scheduled SQL pipeline at Example Logistics."
  - "Built a churn model that flagged at-risk accounts, letting the retention team contact them early, using Python and scikit-learn."
  - "Moved 30 pipelines to dbt and Airflow, ending manual reruns, with tests on every model."
- State data size or user count as scope when there is no result number.

## Keywords and credentials

- Keywords from the ad: SQL, Python, R, Power BI, Tableau, Excel, ETL, data warehouse, dbt, Airflow, Spark, statistics, A/B testing, machine learning, data modelling, storytelling.
- Credentials seen, with issuer: Microsoft Certified Power BI Data Analyst Associate PL-300 (Microsoft); Google Cloud Professional Data Engineer (Google Cloud); AWS Certified Data Engineer Associate (Amazon Web Services); Databricks and Snowflake certifications (Databricks, Snowflake); Tableau certifications (Salesforce). Many analyst ads ask for none; do not present any as required unless the ad does.

## Portfolio and work samples

- Often expected for junior and career-change candidates, less for senior. A good one answers a real question on public data: the question, method, chart, finding and code.
- Never show employer or customer data, even masked, without written permission.

## Screening questions

- "Years of SQL / Python / Tableau": from `experience.items`.
- "Largest dataset handled": answer from evidence with units, or "not measured".
- "Have you built models in production?": answer as it is; analysis in a notebook is not production.
- "Do you hold PL-300 or similar?": true or false from the bank.

## Answer-bank experience keys

Collect lowercase keys with years or true/false: `sql`, `python`, `r`, `excel`, `power bi`, `tableau`, `looker`, `dbt`, `airflow`, `spark`, `snowflake`, `bigquery`, `databricks`, `statistics`, `a/b testing`, `machine learning`, `etl`, `pl-300`, `gcp data engineer`.

## Mistakes to avoid

- Listing tools without a decision or result they supported.
- Putting real customer data in a portfolio.
- Calling a one-off analysis "machine learning".
- Estimating a business impact the person cannot source.
